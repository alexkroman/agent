# API surface analysis

An audit of the published API reference
(<https://alexkroman.github.io/agent/>, generated by `pnpm docs:api`) and of
the built `.d.ts` files, in two parts:

1. **The human-facing API docs** — exports that should be private, doc
   comments that are confusing, wrong, or broken.
2. **The same `.d.ts` surface from an AI coding agent's perspective** — the
   studio coding agent (and users' own Cursor/Claude Code sessions) treat
   `node_modules/@alexkroman1/aai/dist/**/*.d.ts` as ground truth, so this
   part ranks what would actively mislead a code-writing agent.

Method: the docs were regenerated locally from this tree (`docs/dist`,
41 TypeDoc warnings), every documented export was cross-referenced against
its real consumers with grep, and the built `dist/*.d.ts` files were read
end to end. All file:line references are to this repo.

---

## Part 1 — Public things that should be private

### 1.1 Headline numbers

- The main `@alexkroman1/aai` entry exports **105 symbols; 92 are
  constants/values that are not `agent`/`tool`/types**
  (`packages/aai/sdk/__snapshots__/exports.test.ts.snap`). Roughly a dozen
  are genuinely user-facing.
- Of the ~57 documented items on `@alexkroman1/aai/runtime`, **~24 have zero
  consumers outside `packages/aai` itself** — dead public API.
- The `@alexkroman1/aai-cli` docs page consists **100% of internal build
  hooks** (`buildWorker`, `buildClient`, `typecheckProject`) while the
  actual product (the `aai` CLI commands) is absent.
- `knip.json:9-14` excludes `"exports"`/`"types"` from knip, so unused
  public exports are invisible to CI; the only guard is a snapshot test
  that pins the surface rather than questioning it.

Because `docs/typedoc.json` already sets `excludeInternal: true`, tagging a
symbol `@internal` removes it from the docs without breaking the sibling
packages that import it — most fixes below are one-line tags.

### 1.2 Main entry (`@alexkroman1/aai`): eight groups to demote

Evidence of consumers is in the per-group notes; none of these appear in
any template agent (`packages/aai-templates/templates/**`), the real
user-facing corpus.

| Group | Examples | Actual consumers |
| --- | --- | --- |
| Client-audio budgets (13) | `PLAYBACK_JITTER_MS`, `MIC_BUFFER_SECONDS`, `PACER_BURST_MS`, `CAPTURE_STOP_ACK_TIMEOUT_MS` | aai-ui worklets + `host/audio-pacer.ts` only |
| Builtin-tool fetch budgets | `TOOL_USER_AGENT`, `HTML_ACCEPT`, `MAX_PAGE_CHARS`, `MAX_DESIGN_*`, `FETCH_TIMEOUT_MS` | `host/builtin-tools.ts`, `page-design.ts`, `web-search.ts` only |

| Wire/socket limits | `MAX_WS_PAYLOAD_BYTES`, `WS_OPEN`, `LOG_PREVIEW_CHARS`, `MAX_CLIENT_WS_BUFFERED_BYTES` | protocol.ts / ws-handler / aai-server; belong on `./protocol` if anywhere |
| Platform plumbing | `AGENT_CSP`, `parseWsUpgradeParams`, `DEFAULT_HOST_HANDSHAKE_TIMEOUT_MS`, `SESSION_KEEPALIVE_INTERVAL_MS` | aai-server + `host/server.ts` only |

`WS_OPEN = 1` (`sdk/constants.ts:482`) — an undocumented restatement of
`WebSocket.OPEN` — is the emblematic case: it sits on the agent-authoring
entry point between `DEFAULT_GREETING` and the voice constants.

What should remain on the root: `agent`, `tool`, the authoring types
(`AgentDef`, `ToolDef`, `ToolContext`, `Message`, `Db`, `GenerateOptions`
etc.), `assemblyAIPipeline`/`assemblyAIS2s`, and the ~13 `DEFAULT_*`
constants that document an `agent()` field default.

### 1.3 `/runtime` barrel: star exports made the surface accidental

`host/runtime-barrel.ts:17-38` is 15 wholesale `export *` lines — every
new non-`_`-prefixed symbol in those modules silently ships as public API.
The genuinely public core is small: `createRuntime`, `RuntimeOptions`,
`Runtime`, `SessionStartOptions`, `Logger`, `S2SConfig`, `ExecuteTool`,
`safeFetch`, `withHostCredentialFallback`, `createPostgresDb`,
`requiredProviderEnvVars`, `resolveLlm`, `resolveAllBuiltins`.

Zero-consumer exports that should be `@internal` or removed:
`createPipelineTransport`, `createS2sTransport`, `Transport`,
`TransportCallbacks`, `TransportSessionConfig`, `createSessionCore`,
`SessionCore`, `SessionCoreOptions`, `executeToolCall`, `createGenerateFn`,
`HostGenerateFn`, `wireSessionSocket`, `safeSend`, `resolveBuiltin`,
`SANDBOX_ONLY_BUILTINS`, `isDebugEnv`, `debugLoggingEnabled`,
`createConsoleLogger`, `DEFAULT_S2S_CONFIG`, `PROVIDER_CREDENTIAL_ENVS`,
`isPrivateIp`, `resolveAndAssertPublic`, `isPathInside`, plus the whole
host-mode family (`buildHostAgent`, `isHostAllowed`,
`createRelayExecuteTool`, `RelayExecuteTool`, `RelayToolResult`,
`StartHostSessionOptions` — an unauthenticated agent-replacement feature
used only by the tau2 harness; publishing it advertises a foot-gun).

**The four fetch exports are the most confusing cluster on the page**
(`host/ssrf.ts`):

- `safeFetch` (`ssrf.ts:194`) — the real SSRF-guarded fetch. Keep public.
- `ssrfSafeFetch` (`:151`) — NOT an alias of `safeFetch` despite the name;
  it is the lower-level 3-arg engine with a mandatory `fetchFn` parameter.
  Nobody outside `ssrf.ts` calls it. Hide or rename.
- `pinnedFetch` (`:45`) — raw undici fetch, **no SSRF checking**, exported
  "for `ssrf-dispatcher.test.ts`". A reader scanning for "the safe fetch"
  finds the unsafe one first alphabetically. Hide.
- `builtinFetch` (`:221`) — a *selector* that returns a fetch, despite the
  `-Fetch` name. Internal containment policy. Hide.

**`createServer` inconsistency**: `createServer`/`ServerOptions`/
`AgentServer` are `@internal` (hidden), but `SessionRuntime` — whose only
purpose is to type `ServerOptions.runtime` — is not, so the docs show a
type whose sole consumer is invisible. Also `host/server.ts:9` says
"Import via `aai/host`", a subpath that does not exist (it's `./runtime`).
Since nothing documents how to actually *run* a runtime (no example, no
README mention of `/runtime` anywhere), decide whether self-hosting is a
supported story; if yes, promote `createServer` and add an example; if no,
hide `SessionRuntime` too.

### 1.4 `/manifest`, `/utils`, `/protocol`, `/tools`

- **`/manifest` self-describes as internal** ("Used by aai-cli (bundler)
  and aai-server (rpc-schemas)", `sdk/manifest-barrel.ts:2-6`) and it is:
  the `assert*` trio and the Zod schemas have no consumers outside
  aai-server/aai-cli; `ProviderDescriptorSchema` has **zero consumers
  anywhere**. Only `toAgentConfig` (called by generated bundle entries) is
  public-worthy. The barrel also launders symbols out of
  `sdk/_internal-types.ts` — a `_`-prefixed module that CLAUDE.md's own
  convention table declares "not part of the public API" — and that file
  has no module doc, so `AgentConfig` lands in TypeDoc under a nameless
  module. Move the public half (`AgentConfig`, `AgentConfigSchema`,
  `ToolSchema`, `toAgentConfig`, `AgentConfigSource`) into a real module.
- **`/utils`**: `errorMessage`, `errorDetail`, `safeJsonParse` are
  legitimate public utilities. `capToolResult`, `toArgsRecord`,
  `isTextAssetPath` are framework plumbing whose own comments prove it.
  `toolError` has zero consumers — document it for tool authors or drop
  it. The module is also double-published (root *and* `./utils`), so every
  util and the slug constants get two doc pages.
- **`/protocol` opens with "this module is for internal use only and
  should not be used directly"** (`sdk/protocol.ts:5`) — on a published
  subpath whose members are tagged `@public` and which aai-ui imports.
  This is the single most self-contradictory page in the docs. Either
  drop the sentence or unpublish the subpath.
- **`/tools`** (`host/agent-tools.ts`) is the one unambiguously
  user-facing subpath (the scaffold guide tells generated agents to import
  from it) — and it is missing from CLAUDE.md's subpath table entirely.

### 1.5 aai-ui: 11 of ~25 exports are provably internal

Ground truth: the five template `client.tsx` files use `client`,
`useSession`, `useAgentState`, `useEvent`, `useToolCallStart`, `useTheme`,
`Button`, `ChatView`, `SidebarLayout`, `StartScreen`, `ChatMessage`. There
are **no other consumers of aai-ui anywhere**.

Internal-only exports to demote: `ApiUrlChip`, `UiUrlChip`,
`SessionUrlChips`, `ToolConfigContext` (whose index.ts blurb says "for
component-tier custom UIs" while component tier sets `tools?: never` — a
contradiction), `VOICE_CAPTURE_CONSTRAINTS`, `buildAgentUrl`,
`fetchClientConfig`, `ClientConfigResponse`, `SessionProvider`,
`ThemeProvider` (both installed by `client()`, both undocumented).

### 1.6 aai-cli: the docs are inverted relative to intent

`packages/aai-cli` has no `"."` export at all — only `./worker-bundler`,
`./client-bundler`, `./typecheck`, which exist solely so aai-server/the
studio can build workspaces (CLAUDE.md: "Do not widen it"). Their doc
comments explain *why the filename lacks an underscore* but never say
"internal — do not import"; rendered on the docs site, "Public because the
platform's browser studio reuses it" reads as an invitation. Meanwhile the
real user surface (`aai init|dev|test|build|deploy|delete|secret`) is
undocumented on the site.

Fix: `@internal` module tags on all three (removes them from docs), drop
`../packages/aai-cli` from `docs/typedoc.json` or point it at a real
user-facing entry, and note that CLAUDE.md's boundary rule says "two
public bundler subpaths" while the manifest ships **three** (`/typecheck`
is consumed the same way by `aai-guest/studio-build.ts:105,185`).

## Part 2 — Doc comments that are wrong or confusing

### 2.1 Factually wrong (fix first — these mislead humans and agents alike)

1. **`interruptionMinDurationMs` doc says "Default 0 (disabled)"**
   (`sdk/types.ts:301`) — the real default is
   `DEFAULT_INTERRUPTION_MIN_DURATION_MS` = **500**
   (`host/transports/pipeline-transport-options.ts:141-142`,
   `sdk/constants.ts:216`), whose own doc says "Non-zero by default". The
   stale claim is duplicated in the scaffold guide
   (`packages/aai-templates/scaffold/CLAUDE.md:83`, `:209`) — the studio
   agent's system prompt.
2. **`minTurnSilenceMs` doc says the default is 1500**
   (`sdk/providers/stt/assemblyai.ts:46`) — the constant was raised to
   **2000** and its comment explains why 1500 was wrong. The provider doc
   was never updated.
3. **`RuntimeOptions.fetch` says "Defaults to `globalThis.fetch`"**
   (`host/runtime-types.ts:133-139`) and advises passing an SSRF-safe
   fetch "in platform mode" — the actual default is `builtinFetch()`
   (SSRF-screened by construction). A security-relevant falsehood on the
   most-read public type.
4. **`Runtime`'s doc promises a `hooks` member** (`runtime-types.ts:170`)
   that the type does not have; `createRuntime`'s doc
   (`host/runtime.ts:103-114`) says it "builds tool schemas for the S2S
   API" and "wires up lifecycle hooks" — both predate the pipeline work;
   there are no hook fields anywhere.
5. **`sdk/types.ts:224` references "behavioral fields (hooks,
   `sttPrompt`, etc.)"** — there are no hooks on `AgentDef` and no
   `sdk/hooks.ts` in the package.
6. **`sdk/generate.ts:14-15` points at `sdk/workflow.ts`**, a module that
   was removed and is not shipped.
7. **`buildReadyConfig`'s doc says it builds config "from S2S sample
   rates"** (`sdk/protocol.ts:338`) — nothing in it is S2S-specific; a
   pipeline reader will conclude it doesn't apply to them.
8. **`assemblyai-pipeline.ts:12` shows `agent({ name: "Ivy", voice:
   "ivy" })`** — `voice` is not an `AgentDef` field; the snippet doesn't
   compile. (It's a history aside, but nothing marks it as one.)
9. **The main entry's module doc** (`packages/aai/index.ts:2-7`) describes
   the package as "shared fundamentals … used across aai-cli, aai-server,
   and aai-ui" — the landing page of the public SDK never mentions
   `agent()` or `tool()`.
10. **`session-core.ts:2-3` says "Replaces session.ts +
    pipeline-session.ts"** — files that no longer exist.

### 2.3 Types referenced by public signatures but not exported

These are compile-blocking for users (you cannot name the type), not just
doc noise:

- `ConfigTier` / `ComponentTier` / `BaseOptions`
  (`aai-ui/define-client.tsx:30,44,61`) — **`ClientConfig`, the one type a
  `client.tsx` author needs, renders as a union of two unresolvable
  names.** Every option and default (`target` = `"#app"`, `sidebarWidth`,
  `platformUrl`, …) is invisible in the docs.
- `WebSocketConstructor` (`aai-ui/types.ts:178`) — exported and
  `@public`-tagged at source; simply missing from `aai-ui/index.ts`'s
  re-export list. One-line fix.
- `ButtonSize` / `ButtonVariant` (`aai-ui/components/button.tsx:17,25`).
- `Unsubscribe` (`sdk/providers.ts:28`) — return type of the public
  `SttSession.on`/`TtsSession.on`; re-exported by neither barrel.
- `AssemblyAITtsLanguage` + `ASSEMBLYAI_TTS_LANGUAGES`
  (`tts/assemblyai.ts:143,153`) — the declared type of the exported
  `AssemblyAITtsOptions.language`.
- `OpenaiRealtimeVoice` (`s2s/openai-realtime.ts:8`) — not even exported
  from its own module, so the barrel's `export *` can't pick it up.
- `SessionMode` + `PipelineTuning` (`sdk/config-rules.ts`) — used by all
  three `/manifest` `assert*` signatures.
- `AgentConfigSource` (`sdk/_internal-types.ts:68`) — the sole parameter
  type of `toAgentConfig`.
- `ExecuteToolOptions` (`sdk/_internal-types.ts:13`) — a `_internal`
  module symbol that is load-bearing in the public `createRuntime`
  contract via `RuntimeOptions.executeTool`.
- `ResolvedBuiltins` / `BuiltinToolOptions` (`host/builtin-tools.ts`) —
  return/param types of `resolveAllBuiltins`, which has real consumers.
- `TtsOpener`/`SttOpener`, `CreateS2sWebSocket`,
  `CreateOpenaiRealtimeWebSocket`, `S2sSessionConfig`,
  `ExecuteToolCallOptions`, `WsSessionOptions` — leak through functions
  that should themselves be `@internal`; hiding the functions fixes these
  for free.

### 2.4 KIND-constant asymmetry in the provider barrels

Barrels using `export *` leak their `*_KIND` constants; barrels using
explicit lists forgot them. Result: the `/llm` page shows
`ANTHROPIC_KIND` and `GOOGLE_KIND` but not `GATEWAY_KIND`,
`OPENROUTER_KIND`, or `ASSEMBLYAI_LLM_KIND`; `/tts` misses all three of
its KINDs — with no rule a reader can infer. Either export all of them, or
change the descriptor types to string literals (`readonly kind:
"assemblyai"`) so the constants stop being load-bearing. Also missing from
barrels while referenced by exported docs: `ASSEMBLYAI_TTS_HOST`,
`ASSEMBLYAI_LLM_GATEWAY_URL`/`_EU_URL`, `OPENROUTER_BASE_URL`.

### 2.5 Naming collisions

- **Three factories named `assemblyAI`** (stt/tts/llm). The aliasing
  warning exists in the TTS module doc (complete), the LLM module doc
  (mentions only two of three), and the STT module — the one a reader hits
  first — **not at all**. The warnings are module-level, so the barrel
  pages readers actually land on never show them. `assemblyAIS2s` proves
  the suffixed-name pattern is acceptable; at minimum hoist the three-way
  warning into all three barrel docblocks and onto each factory.
- **`ClientEvent` is server→client while `ClientMessage` is
  client→server** (`sdk/protocol.ts:194,286`) — two public types whose
  shared prefix means opposite directions, unremarked.
- **Two unrelated `SessionCore`s** (server `host/session-core.ts` vs
  browser `aai-ui/session-core.ts`) — known, but both are documented on
  one site with no cross-note.
- **aai-ui's `CustomEvent` shadows the DOM global** in a `.tsx` package,
  is structurally incompatible with it, and no user ever needs to name it
  (`useEvent` hands over only `.data`). Rename to `AgentCustomEvent` /
  `SessionEvent`; there are no external consumers to break.
- `ClientConfigResponse` and `SessionErrorCode` each get **two doc pages**
  (aai and aai-ui re-export the same type) with no `@inheritDoc`.

### 2.6 Maintainer archaeology rendered as user docs

A consistent pattern: rationale written for repo maintainers ships as the
primary description of public API. Worst offenders:

- `host/agent-tools.ts:2-44` — ~40 lines of eval postmortems ("nine
  separate runs wrote `ctx.fetch_json(...)`") before any usage guidance,
  on the *most* user-facing subpath.
- `sdk/env-types.ts` — tells readers to "see CLAUDE.md" and describes
  functions they cannot import.
- `sdk/types.ts:74-76,236-242` — `NoInfer` mechanics and "the inline
  re-declaration this replaces" on `agent()`'s parameter type.
- `hooks.ts:147-151` (aai-ui) — "58% of measured generated agents" with no
  referent.
- `RuntimeOptions.stt` (`runtime-types.ts:148-158`) — six lines on the
  history of a removed escape hatch, referencing an unexported
  `registerSttKind`.
- `StartHostSessionOptions.env` — a nine-line `ws` handshake postmortem.
- `HostConfigSchema` (`protocol.ts:291-298`) cites `HOST_MODE_CONTRACT.md
  §§3-5` and "a tau2 harness" — neither shipped nor explained.

Where the rationale is valuable (often!), move it to a `//` code comment
or an `@remarks`-after-the-user-facing-summary so the first paragraph
serves the reader.

### 2.7 Load-bearing API with no docs at all

- **`AgentDef`'s nine most-used fields are undocumented**: `name`,
  `systemPrompt`, `greeting`, `sttPrompt`, `maxSteps`, `toolChoice`,
  `builtinTools`, `idleTimeoutMs`, `state` (`sdk/types.ts:229-244`).
  `idleTimeoutMs` doesn't state the 300 000 default or that `0` disables;
  `sttPrompt`'s only explanation lives on `DEFAULT_STT_PROMPT`, unlinked.
- **`useSession()` has zero doc** (`aai-ui/context.ts:55`) — the
  most-imported hook in the templates. It also throws
  "must be used within `<SessionProvider>`", naming a component the user
  was never told about (installed by `client()`).
- **`useEvent` and `useToolCallStart` are undocumented** while
  `useToolResult` — the pattern the templates were migrated *away* from —
  carries 13 lines. The docs steer first-time authors to the old pattern.
- `ToolContext.send` never mentions the silent size limits
  (`MAX_CLIENT_EVENT_NAME_LENGTH`, `MAX_CLIENT_EVENT_PAYLOAD_BYTES`) that
  drop the event; `ToolDef.execute` never mentions the 4 000-char
  truncation (`capToolResult`).
- `SessionCoreOptions` (aai-ui) is a bare alias of `VoiceSessionOptions`
  with no comment — two public names for one type, unexplained. And
  `VoiceSessionOptions.platformUrl` is required while `client()`'s hidden
  `BaseOptions` makes it optional — the type a reader *can* see disagrees
  with the one they can't.
- `TypecheckResult` (aai-cli) is a bare discriminated union, no comment.

## Part 3 — The `.d.ts` files from an AI coding agent's perspective

Good news first: JSDoc preservation through the build is excellent —
multi-paragraph comments, `@example` blocks and links all survive into
`dist`. `dist/sdk/constants.d.ts` is a model file (units, rationale,
arithmetic relationships). Almost every issue below is a source-level gap,
not a build loss. Ranked by how badly each misleads a code-writing agent:

1. **Wrong defaults an agent will copy verbatim.** The
   `interruptionMinDurationMs` "Default 0" and `minTurnSilenceMs` "1500"
   errors (§2.1) are worse for agents than humans: an agent reads
   `AgentDef` first, trusts it, and the contradicting constant is in a
   file it has no reason to open. The wrong default is *also* in the
   scaffold CLAUDE.md the studio agent is prompted with — the error is
   served to it twice.

2. **The recommended entry point recommends deprecated voices.**
   `dist/sdk/providers/assemblyai-pipeline.d.ts` documents
   `voice?: string` with examples `"ivy"`, `"james"` — both in
   `ASSEMBLYAI_TTS_DEPRECATED_VOICES` — and its module doc uses
   `voice: "ivy"` three times, plus a history snippet showing the
   removed top-level `agent({ voice: "ivv" })` form. A wrong voice id
   fails *in-band after connect*: the agent deploys, reports ready, and is
   permanently silent (the exact failure mode CLAUDE.md's Voices section
   was rewritten to kill — it survives in the built output). Fix: type
   the field as `AssemblyAITtsVoice`, link `ASSEMBLYAI_TTS_VOICES`, use
   current voice names in every example.

3. **Every module specifier in `dist/index.d.ts` points at a file that
   does not exist.** The built entry re-exports
   `"./sdk/constants.ts"` / `"./components/button.tsx"` — source
   extensions — while the shipped files are `.d.ts`. `tsc` substitutes
   silently, but an agent navigating with `cat` (the studio agent's
   documented workflow) gets `No such file` on the first hop off
   `index.d.ts`, every time, in both packages. Fix in the build config,
   or add one line to the studio prompt/scaffold: "rewrite `.ts`/`.tsx`
   to `.d.ts` when reading dist".

4. **`SttProvider`/`TtsProvider`/`LlmProvider`/`Unsubscribe` type
   `AgentDef.stt/llm/tts` but are not importable from the root** —
   `sdk/providers.d.ts` is not re-exported from `index.d.ts`. An agent
   writing `function pickTts(): TtsProvider` must already know the
   `/tts` subpath exists. Dangling `{@link SttOpener}`-style references
   (§2.2) compound this: an agent that greps for a linked symbol and gets
   no hit may conclude it was removed.

5. **Three identical `assemblyAI` declarations in a grep.** The STT file —
   whose types are named plainly `AssemblyAIOptions`/`AssemblyAIProvider`
   as if they were the umbrella — carries no collision warning; the LLM
   file's warning names only two of three. The complete warning lives
   only in the TTS file.

6. **The voice catalog is excellent but unreachable from where an agent
   starts.** `ASSEMBLYAI_TTS_VOICES` in `dist/sdk/providers/tts/
   assemblyai.d.ts` inlines all 16 voices with language + accent —
   exactly right — but the root entry re-exports only
   `assemblyai-pipeline` (whose `voice` is an untyped `string`, see #2),
   so the recommended path never crosses the catalog. Also: the catalog
   documents `accent` as data but `AssemblyAITtsOptions` has no `accent`
   knob (an agent may try to pass it), and nothing mentions the default
   voice (`vera`) is UK-accented.

7. **`ChatMessage.role` (aai-ui) is `"user" | "assistant"` while the
   SDK's `Message.role` adds `"tool"`.** Same concept, different unions,
   no cross-reference — an agent writing a role switch in `client.tsx`
   may add a dead `"tool"` branch or assume tool calls arrive in
   `messages` (they arrive in `toolCalls`).

8. **The hook docs steer agents to the deprecated pattern** (§2.7):
   `useEvent` — the recommended pairing with `ctx.send` — is
   undocumented and never says it pairs with `ctx.send`; `useToolResult`
   has the long docstring.

9. **Likely real type error in shipped d.ts**:
   `aai-ui/dist/components/button.d.ts:47` references
   `React.ButtonHTMLAttributes` but the file imports only
   `{ ReactNode }` — no `React` namespace import. Under React 19 types
   with `skipLibCheck: false` a user's tsc may reject the package.
   (`attw`/`publint` run with skipLibCheck and won't catch it.)

10. **`loadClientConfig` trap**: `aai-ui/dist/client-config.d.ts` exports
    it with a 15-line doc, but `index.d.ts` re-exports only
    `fetchClientConfig`. An agent grepping dist finds the
    better-documented function and imports something unavailable from
