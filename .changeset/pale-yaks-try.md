Push a run's state to a page instead of making it poll. `GET /workflows/runs/:id/events` streams a run as server-sent events, and `useWorkflowRun` takes its state from that stream, keeping the poll as the FALLBACK for every way a stream can fail — an agent deployed before the route existed, a proxy that buffers, a dropped connection, or the stream's own duration cap handing itself back. The saving is specific: on the platform every polled read BROKERS, so N open tabs at a 2s interval is N/2 brokered requests a second, each able to boot a sandbox. SSE rather than a WebSocket because `page()` deliberately constructs no `SessionCore`, and a `fetch` stream rather than `EventSource`, which cannot send an `Authorization` header (an agent with `AAI_WORKFLOW_API_TOKEN` would be unreachable) and reconnects on a schedule that fights the caller's. The stream watches by reading the store in-process — one indexed query next to the run, with no HTTP hop and no brokering, which is the cost the stream exists to remove — and the platform's forwarder registers the relayed stream with `live-streams.ts`, without which a scale-in would cut the chunked body before its terminating frame.
