Add per-user scoping to the workflow API. `createServer({ identifyWorkflowCaller })` resolves who is calling, and every run is stamped with that identity (`owner_scope`) and filtered by it on every read and mutation — `get`, `find`, `recent`, `cancel`, `retry` — so one user cannot see or steer another's run. Until now the only posture available was all-or-nothing (`AAI_WORKFLOW_API_TOKEN`, one shared bearer), and a shared bearer in a browser bundle is not a secret: a page could be a public toy or a single-tenant internal tool and nothing with a notion of this user's runs. The SDK deliberately supplies NO user model — these are the app's users, and binding them to a provider of ours would couple every deployed agent to it — so `identify` verifies whatever the app already has. Declaring it makes the API fail CLOSED, the opposite of the token's posture; the token becomes the OPERATOR credential and bypasses the filter, which is what `aai workflow runs` and the studio card need. Two properties worth knowing: a scoped read does not match a NULL scope, so runs created before an app declared `identify` belong to nobody rather than to whichever user asks first; and a continuation INHERITS its predecessor's scope, without which `ctx.continueAs` would launder a run out of its owner's view mid-chain.
