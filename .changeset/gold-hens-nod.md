Add `ctx.waitFor(name)` — a durable waitpoint. A run parks until `POST /workflows/signals/:token` resolves it, and `waitFor` returns the payload that call sent. This is the shape `ctx.sleep` cannot express: human-in-the-loop. With `sleep` an approval is a poll — wake, check, sleep — and every cycle burns entries against `MAX_WORKFLOW_STEPS` (500), so a wait measured in days is not expressible at all; a waitpoint costs ONE journal entry however long it waits. The token is an unguessable single-use id and IS the authorization, so the signal route needs no run id and the URL is safe to email; `announce` delivers it, running exactly once (journaled) while the run is still executing, which is the only moment the token exists and the run can act on it. `timeoutMs` reuses the existing wake machinery — a parked run with a deadline is due exactly like a sleeper, so `runDue()` and the platform wake sweep recover it with no second mechanism — and the wait throws at the deadline so a `try`/`catch` expresses "chase them, then give up". A parked run is `sleeping` with no wake time rather than a sixth status, so `isTerminal`, the page's poll, the `workflow_status` builtin and the studio card all render it correctly unchanged.
