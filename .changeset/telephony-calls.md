Phone calls an app PLACES: call identity, refusing a session, and hanging up from a tool.

- **`call` on a `WS /phone` session.** The carrier's `start` frame is now decoded for the call's identity — Twilio's `start.callSid` and `start.customParameters` (the `<Parameter>` elements of `<Connect><Stream>`), Telnyx's `call_control_id`, `custom_parameters` and Call Control's `client_state` (surfaced as a parameter of that name, still base64). Bounded: at most 32 parameters, each name plus value under 500 characters, non-string values dropped; a call id over 128 characters is dropped. `sessionContext` and `onSessionEnd` receive it as `call?: SessionCall` (`{ carrier, callId?, parameters }`), and a tool reads it with `sessionCall(ctx)`. A phone session now starts once the carrier's `start` frame has arrived, so `sessionContext` sees it; a stream that sends none within `TELEPHONY_START_TIMEOUT_MS` (5 s) is closed with 1008, and one that closes first starts nothing.
- **`SessionContext.refuse`.** `sessionContext` may answer `{ refuse: "<reason>" }`: the session is closed before the greeting and before any model call — a WebSocket client with a 1008 close carrying the reason (no `error.reported`), a phone call by closing the carrier stream, which hangs up. Logged once at warn with the session id, the transport and the reason (trimmed, control characters replaced, capped at 200); `onSessionEnd` does not fire for a refused session.
- **`endSession(ctx, { afterReply? })`.** A tool ends its session — a phone agent's `end_call`. By default the current reply finishes PLAYING first (the paced sink waits for its `reply.completed` and the playout clock, plus 500 ms), bounded at 30 s; `{ afterReply: false }` ends it now; a barge-in on the goodbye ends it at once. The end is a normal stop: a normal (1000) close, the session's events flushed, `onSessionEnd` fired. For `WS /phone` the carrier stream is closed, which with `<Connect><Stream>` and no further TwiML hangs the call up. Returns `false` when there is no live session. Tested with `endSessionCalls(ctx)` from `@alexkroman1/aai/testing`, which records every request a `createToolContext` context's tools made; `createToolContext({ call })` seeds `sessionCall`.
- **`aai dev` proxies `/phone`.** With a `client.tsx`, the Vite front on the printed port now forwards `WS /phone` to the runtime backend (whose port is picked at start), so a tunnel pointed at the printed port reaches the agent. Without a `client.tsx` the runtime serves the printed port directly.
- `TelephonyBridgeOptions.onStart`, `startTelephonySession`'s `startTimeoutMs`, and the optional `callId`/`parameters` on `CarrierInbound`'s `start` variant (a hand-written codec that omits them still type-checks).
