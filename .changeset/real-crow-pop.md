Remove the fast/slow two-tier architecture, write the voice identifier rules as SPELLING rules, and regenerate the gateway model catalog.

**`agent({ twoTier })` is gone**, along with `TwoTierConfig`, the six digest/tier constants and `ToolDef.mutates` / `ToolDef.completes`. It did not survive its own measurement: graded on `retail-orders-agent`, a digest entry records a tool NAME and never a result and each caller utterance builds a fresh slow-tier loop whose only memory is that digest, so reads were re-called every utterance, a terminal transfer LOOPED, and one session spent 252,825 tokens against a 200,000 cap. An agent that declared the field no longer compiles; the WIRE schema strips the two tool classifications rather than refusing them, so a bundle minted by the older SDK still deploys and simply carries nothing.

**The identifier rules in the default prompt are now rules about how to WRITE an id, not how it sounds.** "Spoken one character at a time" is not a thing a model that only chooses characters can comply with, and across 1,811 tau2-bench retail calls 2.8% of agent turns still carried a bare `W`-plus-digits order number and 3.4% a bare digit run of seven or more — both worse in the newest runs than the oldest. Synthesized through AssemblyAI TTS and read back with formatting off: `#W2378156` is spoken "W two million three hundred seventy-eight thousand…" and `W-2-3-7-8-1-5-6` digit by digit. So an id is hyphenated end to end with the "#" dropped; a digit-only code (a card's last four, an item number, a ZIP, a phone number) counts as an identifier for the first time; an email gets a three-part rule of its own; an amount under a dollar is cents alone and a date is written in words; and a value the caller has to write down goes in the FIRST sentence. TOOLS' "copy values exactly" is SCOPED to tool arguments, because unqualified it was an instruction to speak the id exactly as the tool result spelled it.

**The gateway liveness probe sent `max_tokens: 1`**, which a reasoning model refuses before emitting a content token — so one regeneration read the entire gpt-5 family as dead, the default model included, and would have dropped it out of `gatewayModelIds()` and the studio's model picker. The budget is 64 now. With it fixed: `claude-opus-5`, `gemini-3.7-flash`, `gemini-3.8-flash`, `gemma-4-31b`, `gpt-5.6-sol` and `gpt-6-astra` join the catalog, `kimi-k2.5` leaves (410), `gemini-3.6-flash` comes back live and EU, and `ASSEMBLYAI_LLM_DEFAULT_MODEL` moves to `gpt-5.6-sol` — same family and the same side of `TOOLS_REQUIRE_NO_REASONING` as the id it replaces, re-measured 5/5.

**And a scaffolded project no longer fast-refreshes a prebuilt `dist/` or its own `client.tsx`.** Both are refresh boundaries the plugin cannot refresh, so each was re-executed and only then discarded for a page reload: one rebuild of a linked `@alexkroman1/aai-ui` produced 33 partial updates, 12 invalidations and 8 throws of "Session hooks must be used within <SessionProvider>".
